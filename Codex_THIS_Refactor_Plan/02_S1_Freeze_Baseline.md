# S1｜冻结可复现基线（需用户批准 S0 之后单独执行）

**目标：在任何文件移动之前创建可审计的基线。除 `docs/refactor/` 中审计产物外，不变更算法、报告与正式结果。执行后停止。**

开始前：检查 `git status`。如果有未提交变更或大文件未跟踪，列明风险并要求用户选择保护方式；不得直接丢弃、覆盖或擅自提交敏感文件。分支/标签名称和 commit 行为须先向用户确认。

要求：
1. 记录当前 git commit、依赖版本和必要的环境重建方法；确认原始论文目录的文件哈希。
2. 针对正式 R5 `e1_full_independent` 生成**只读 manifest**（路径、大小、SHA256）。保留初值独立性修正、中止批次的审计证据（可归档，不可删）。
3. 找到/生成轻量 golden fixture：至少固定一个有噪声 trial 及一个零噪声 trial 的同一数据切片；记录输入数据 hash、Taylor `theta/d`、标准化均值/尺度、Ridge 初值与权重、选中 alpha、模型状态、恢复系数、边 score、TP/FP/FN 与结构解码。**如原始产物不含逐项字段，请标明缺失，须经批准才能运行新的基线生成命令。**
4. 先执行已有单元测试、最小规模兼容检查，不自行运行 30-seed 全量，也不对历史 `selection_locked.toml` 重写。
5. 基线必须保留 `M1/M2` 在 0% 噪声的 BIC NA；保存既有警告；不做参数修复。
6. 对比报告的关键三体 F1：5% M0/M1/M2/M3 = 0.6700/0.8363/0.8769/0.4960；10% = 0.6700/0.8363/0.8224/0.4234；20% = 0.6600/0.7995/0.6681/0.3489。**这只是审计哨兵值，不能使用它们选择参数。**

交付：`S1_baseline_manifest.csv`, `S1_baseline.md`, `S1_test_results.md`, golden 数据索引及哈希（放 `docs/refactor/` 或已有 tests fixtures 合规位置）。

判定：基线缺失、测试失败、结果无法归因时标为 BLOCKED 并停止；严禁跳到重构。完成后等待用户批准 S2。
