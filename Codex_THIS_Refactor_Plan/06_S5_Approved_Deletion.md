# S5｜执行用户逐项批准的删除（高风险单独授权阶段）

**只有在用户已经审阅并明确批准 S4 中列出的具体文件路径后，才能执行。若缺批准名单、哈希不一致、文件近期有变化，立刻停止。**

执行原则：
1. 仅处理逐项 `approval_status=APPROVED` 且路径、hash、恢复路径与批准记录一致的文件；批准“某一类文件”不等于批准任意同类全部文件。
2. 删除前复核 `git status` 和依赖扫描；对 tracked 文件优先经 `git rm -- <exact path>`（仍需确定批准），对 untracked 文件逐个按 exact path 处理；禁止通配、递归目录清理、`git clean -fdx`。
3. 任何拟删文件若被正式证据、活动 CLI、测试或未完成 R4/E2/E3 引用，改为 BLOCKED，保留。
4. 每删除一个经过批准的批次，运行轻量 tests 和关键 CLI `--help` 或 dry-run，核对文档索引引用仍有效。
5. 记录 `docs/refactor/S5_deletion_log.csv`: 批准者与批准日期、路径、删除前 hash、原因、还原手段、测试状态；保留安全恢复方法。
6. 若环境中没有可恢复的快照，无法删除；先请求用户批准创建备份。

完成后输出确切删除文件数和净节省空间；不能将失败隐瞒为成功。**停止，等待用户批准最终 S6。**
