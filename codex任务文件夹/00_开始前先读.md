# THIS + Adaptive LASSO：Codex 分阶段执行说明

本套件提供六份相互独立的阶段任务文件 `R0`–`R5`。**不要把六份文件同时提交给 Codex**，也不要一次性要求 Codex 完成整个项目。

## 本阶段唯一科研问题

保留 THIS 的 Taylor 多项式特征生成和高阶结构解码，比较原始 STLSQ、标准 LASSO 与 Ridge-initialized Adaptive LASSO 的稀疏恢复质量，重点验证含噪条件下三体交互 Precision / Recall / F1 / AUPRC 是否改善。

**不在本轮实现**：Pearson 候选预筛选的新方案、跨阶特征分组/纠错、H 与 SC 分类器、四体及以上交互、大规模并行优化。无论 Codex 给出什么建议，先记在 `future_work.md`，不要直接动代码。

## 使用方法（每个阶段严格相同）

1. 在 VS Code 中打开你的研究项目根目录。让 Codex 先阅读且只执行**当前一份** `R*.md`。
2. Codex **首先做环境/文件检查，列出本阶段拟编辑的文件与执行步骤**，确认没有跨阶段修改后再开始本阶段工作。
3. 本阶段结束时，Codex 必须提供：实际修改文件列表、命令及测试结果、已知问题、学习解释、研究进度清单。
4. 你亲自运行关键命令，勾选该 `R*.md` 底部研究进度检查表，并在 `总研究进度检查表.md` 中更新。
5. **只能由你发出下一次新指令启动 R(n+1)**。Codex 不得提前准备下一阶段实现。
6. R4、R5 要求先只执行最小 smoke/dry run，等待你确认后才可以大规模重复试验。

## 给 Codex 的统一最高优先级规则

- 阶段隔离：只执行当前 R 文件描述的任务；不实现 R(n+1)、不顺带重构全部项目、不主动训练分类器。
- 可验证：每次运行写明真实命令、环境、退出码、日志位置；不能凭空宣称实验成功或论文图复现。
- 保留上游：`upstream/THIS` 和 `upstream/Su-AdaptiveLASSO` 只读；不得直接覆盖作者源码。源码仓库 HEAD commit、许可和依赖版本要记录。
- 科研诚信：不得调真值、不得用测试集标签选参数、不得选择单个最好 seed 充当均值、不得伪造 MCC/F1。
- 有阻塞就停：缺少 Julia、GitHub 连接失败、测试失败、接口不一致时，说明原因并请求用户决定；不要静默跳过。
- 教学解释：用中文说明本阶段的核心公式、维度、函数入口以及为何采用当前步骤；最多提出 3 个供用户自己思考的问题。
- 文件边界：除本阶段列出的文件外不得修改；若确需修改，先提出理由并等用户同意。
- 阶段结束必须停止，最后写明：`R? 完成/未完成；等待人工验收；未执行下一阶段。`

## 基本数据契约（R0 产出正式版本）

- Julia 状态、导数 `X`, `Y`: `[N, K]`；Taylor 特征 `θ`: `[P, K]`；单项式节点索引 `d`: `[P, dmax]`；系数 `Ξ`: `[N, P]`。
- Python 回归设计矩阵 `X_design = θ.T`: `[K, P]`；目标节点的 `y`: `[K]`。
- Julia 索引从 1 开始；不得丢失 `d`、不得重排 Taylor 特征、不得把多项式次数直接等同于交互阶数。
- 数据分割按独立轨迹/初始条件，训练集拟合的任何归一化、权重和正则参数不得泄漏测试数据。
