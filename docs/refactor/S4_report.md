# S4：删除候选清单与依赖检查

日期2026-10-20。本阶段只做dry-run，未删除文件。用户已授权连续S3–S6并取消中间验收；S5将基于同一逐路径清单、备份验证和该委托授权继续，不再要求人工逐项确认。

- [静态依赖边](S4_dependency_edges.csv)

共扫描31,624个文件/链接，记录65,648条静态引用边。仅6,385个单硬链接CPython3.11 `.pyc`列为候选，合计144,095,231字节（137.42 MiB）。每个缓存均存在项目内原始.py源文件、magic匹配，已按对应优化级别在内存中重新compile验证，不执行模块、不写入原环境。每个文件都有精确恢复备份计划。

1,140个共享/硬链接Python缓存保留，因为unlink不释放其最后物理链接；44个Julia原生编译缓存保留，不把扩展/JLL加载的恢复假设等同于普通Python缓存。源码、环境锁、包/动态库、所有科研配置/报告/数据/结果、NA/警告/弱边、smoke/aborted、M0s/M1v及后续计划均不进入删除名单。没有以重复文件哈希作为删除科研快照的理由。

引用检索覆盖当前Python import、Julia include/路径、TOML/JSON、shell、文本日志、CSV和Markdown路径。缓存在S0/S1等全树清单中的记录标为审计账目引用，后续删除由S5日志与备份关联，不更改旧清单。任何操作性路径引用或恢复证明不充分的对象转为UNKNOWN保留。

动态加载仍是静态扫描盲点：解释器可能动态读取可选字节码，第三方库也可能拼接路径。安全依据是原源文件存在且可编译、字节码可缺省、逐文件精确备份及删除后真实测试，而不是声称“没有任何引用”。不生成一键危险删除脚本。

S5前必须再次检查每个候选路径、文件身份/哈希、源文件哈希、单链接状态以及备份所有成员的字节。空间数字是删除前缓存逻辑体积；净空间须扣除恢复备份及审计产物，并单独报告实际分配块估算。
