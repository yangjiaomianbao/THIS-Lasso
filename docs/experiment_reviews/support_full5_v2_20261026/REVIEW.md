现有 `fair_comparison_v2_full_run01` 是 10 网络×3 数据重复、两档噪声、三种验证选参方法，共 900 记录。它不能整体当作 A 的固定网络重复，也没有原 STLSQ raw/std 和 BIC。其数据、普通/Adaptive 验证结果可在逐项核对数据、噪声、参数、源码和数值语义后用于 B 的匹配配置，不能直接改标签混用。预算未扣除这种可选复用。

原 96 个 OK 最终系数可复用计算 Q1/Q2。现有逐 alpha 日志有 MSE、非零数和 KKT，但通常没有保存所有候选系数；BIC 保存 alpha/criterion 路径和最终系数。故原路径的结构指标、原尺度容差支持集、逐样本验证损失不能仅靠这些日志还原，需单独补算。保留原结果，给重放路径建立独立诊断记录。

## 执行前需要锁定的科学口径

1. **支持集的尺度与截距。** 同时输出原单位和标准化坐标的支持数；主要比较排除常数/自由截距，另列包含常数的总数。精确非零只作浮点诊断。相对容差须预先固定，推荐额外报告响应归一化贡献 `abs(beta_j)*RMS(theta_j)/std(y_train)`，尺度全部从训练数据估计，单独处理常数。
2. **物理分组与原生读出分开。** 多坐标映射后排除目标物理节点，再按剩余不同物理源数分组。常数、自身、一个外源、两个外源及其他项分开。全部项的物理分组统计不能悄悄替换原 THIS 结构读出；有些函数项参与回归但不被原二/三体读出使用。明确报告这部分支持数及权重。
3. **“过多”不能只用绝对数量定义。** 同时比较解析三阶支持集、原尺度/标准化容差、函数级 FP/FN、预测结构和验证误差。Kuramoto 的解析参考依赖截断阶数与中心，拟合也可能用额外项补偿截断误差；不能把所有额外项自动认定为无意义假项。GLV、SIS、Lorenz、SL 的多项式参考更直接。
4. **alpha 是逐方程选择的。** 现有每个目标方程都有自己的 alpha_max 和所选 alpha。模型级路径应按共同 alpha_fraction 索引组合各方程系数；另保留方程级原始 alpha。不能把不同方程相同绝对 alpha 或不同方法的 alpha 数值直接比较。BIC 的 LARS 折点数也不同于验证的 12 点网格，应分别保存原始路径和必要的对齐诊断。
5. **1-SE 需明确不确定性来源。** 当前是固定训练/验证划分。可从 256 个独立验证初值的逐样本平方误差估计 SE，定义“固定留出验证集的 1-SE 式规则”，不是交叉验证 1-SE。选择满足误差容差的最大 alpha。最好同时分析逐样本配对损失差；跨数据种子 SD 不能充作当前模型选参 SE。如果改成五折 CV，会增加训练重拟合成本，本预算不含它。
6. **解码阈值与回归路径分别控制。** 阈值扫描固定模型系数；alpha 扫描固定原解码规则。未截断的连续分数 AP 在单独改变二值判定阈值时保持不变；F1、Precision、Recall、MCC 会变。若预先把小分数归零再算 AP，那是另一个分数变换，应另标识。
7. **事后真值诊断与可用选参分开。** 用真值寻找的最优结构 alpha/阈值只能作为 oracle 参考，不能报告成不依赖真值的选择方法。测试导数只用于最终/锁定模型评价；看过测试结果后调整的规则，需新数据验证。
8. **原六方法和后续公平验证比较分开。** 原 STLSQ 使用固定默认阈值，LASSO val 有参数搜索。它们可回答当前流程的问题，不能把优势全部解释为 LASSO 机制。另有现成 STLSQ_val 公平对照，可单列分析，不能替换原 raw/std。
9. **Q4 设置有限预算。** 在数据/验证支持数、误差和预测得分分层中预先确定代表模型及候选组，真实标签只用于事后分组。一个可估计的示例上限是 5 系统×3 噪声×2 验证方法×1 个预声明数据种子×10 组=300 次组删除诊断，局部竞争空间不超过 128 列，用 QR/SVD。删除后是否固定 alpha、权重、其余库都要记录。局部竞争集重拟合与全库重拟合是不同实验；只有前者和固定参数的有限诊断包含在下述 Q4 预算中。全库重新选参 300 次可能另增数天，不能按几小时承诺。

Q4 不能从 `K>P` 推出某候选必为假边。零训练投影残差可能是高维插值或冗余，也可能涉及真项可替代性。需要共同查看独立验证贡献、奇异值、竞争空间维数和真实/虚假组的事后分布。

本实验仍是独立 t=0 状态及解析导数，不检验长期轨迹的同步、稳态或吸引子塌缩；有关同步的证据见 `reports/synchronization_audit_20261026/REPORT.md`。

## 实测运行依据

- 原六方法两种子、120 记录批次总墙钟 1,208 秒（20.1 分钟）；运行采用多个系统并行、各自节点进程池，不能直接当作 8 worker 的吞吐。
- 多网络 V2 的 900 记录总墙钟 36,534 秒（10.15 小时），8 worker、BLAS=1，节点 CPU 合计 54.11 小时，观察到的 CPU/总墙钟比约 5.33。
- V2 普通/Adaptive 验证 LASSO：0% 合计 4.88 CPU 小时；5% 合计 41.42 CPU 小时。第三档 10% 尚未测量，不能默认与无噪声相同成本。
- 5% 的 Lorenz 两种 LASSO占 29.39 CPU 小时，SL 占 10.58 CPU 小时，主要成本集中在这两类。原批次的部分回退节点也达到数百秒。
- 以 10% 成本为 5% 的 1/1.5/2 倍作情景，A 的两个验证方法本身约 16.45/20.34/24.22 墙钟小时，尚未计 BIC、数据、路径结构诊断和新增实现开销。固定原网络与多网络样本的难度不同，因此使用较宽预算。

新拟合应一次导出 12 个候选系数/稀疏支持、逐样本验证损失和训练误差，避免拟合完再重跑。LARS 一条路径可评估多个 alpha；无需机械地按 12 倍完整拟合估算。已有路径若候选系数缺失仍需重放。

## 建议的执行方式

先完成原 96 个有效系数的支持集与物理结构对应统计，作为不重拟合的交付。随后把路径导出和状态恢复加入新运行，固定完整种子表、10% 噪声规则、alpha 网格、相对容差及保守选择规则，再开始 A。Q4 仅按预声明触发条件和有限预算开展；B 单独汇总网络级不确定性。额外试跑只用于校准运行时长、内存和输出契约，不按结构分数替换种子或调整候选库。

可用原两个种子新增的 10% Lorenz/SL 路径作为计算校准组合；同时补齐其他三类的同一契约检查。校准后更新预算，不以其测试 F1 选择算法设置。
