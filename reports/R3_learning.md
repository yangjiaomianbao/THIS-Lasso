# R3 学习笔记：从 Taylor 特征到三体交互

## 这次替换的是哪一步

原始 THIS 流程为 `get_θd(X,dmax) → mySINDy(theta,Y) → 系数过滤与 Ainf 解码`。R3 保留两端，只让中间求系数的步骤可切换。入口在 [this_adapter.jl](../src/this_adapter.jl)：

```julia
out = run_this_solver(Xtrain, Ytrain, [2, 3], 3;
    solver="adaptive_lasso",
    config=Dict("selection" => "validation"),
    validation_X=Xval, validation_Y=Yval,
    train_groups=train_ids, validation_groups=validation_ids,
    work_dir="results/r3/一个新的空目录")
```

`out` 为命名元组：`Ainf`、`coeff`、`relerr`、`theta`、`d`、`diagnostics`。预测为 `out.coeff * out.theta`。Python 路径的偏置已进入常数列，没有另加截距。STLSQ 路径直接调用原生 `this`，再检查私有解码与原生 Ainf 完全一致。

| 数据 | Julia/CSV | Python 内部 |
| --- | --- | --- |
| 训练状态与导数 | X、Y 为 `[8,1536]` | 桥接只需 Y；每节点 y 为 `[1536]` |
| Taylor 库 | theta 为 `[165,1536]` | `X_design=theta.T`，即 `[1536,165]` |
| 单项式索引 | d 为 `[165,3]`，保留 1 起始节点号、0 填充 | 原样保留，不用于 Python 数组索引转换 |
| 系数 | coeff 为 `[8,165]` | 每次拟合一个节点得到 `[165]`，按节点叠成矩阵 |
| 验证数据 | 状态、导数 `[8,384]` | 只评价 alpha 候选；训练均值和权重不变 |

## 实际例子：x₅*x₆ 怎样回到 7←{5,6}

本次 [feature_trace.toml](../results/r3/feature_trace.toml) 保存了完整实例：

1. Julia 原生 `get_θd` 得到第 **138** 行，`d[138,:]=[0,6,5]`。去掉 0 后表示乘积 x₆*x₅。`theta[138,k]=X[6,k]*X[5,k]`，顺序来自 THIS，不自行重建或排序特征库。
2. Julia 将 theta、Y、d 写入 CSV，Float64 使用 `%.17g`。metadata 保存 P=165、d 的 495 个索引条目，以及 `monomial_indices.csv` 原始字节的 SHA-256。
3. Python 读取保持二维，再转置 theta。Julia 第 138 个特征成为 Python 第 **137** 列；d 中的 5、6 仍是节点号 5、6。针对 Julia 目标节点 7，Python 取 `Y[6,:]` 作为响应；这里的减 1 只用于访问目标矩阵行。
4. Adaptive LASSO 只用训练集算 Ridge 初值、w 和 a。在缩放库 U 上求 theta_coef，按 `beta=a*theta_coef` 还原。得到该列系数 **0.19999982683956946**；写入回传矩阵的 Python `[6,137]`。
5. Julia 检查请求/返回哈希和矩阵形状后，读取 `coeff[7,138]`。解码先排除重复源，再确认目标 7 不在源集合 {5,6}，并检查绝对值严格大于 10^-8。
6. 两个不同源加一个目标，阶数为 3，写入 `Ainf[3]` 的一行 `[7,5,6,0.19999982683956946]`。解码时排序源节点，不改变 theta 或 coeff 的列顺序。

同一特征的三个实际系数：

| 求解器 | coeff[7,138] | 解码身份 |
| --- | --- | --- |
| STLSQ | 0.19999999999999976 | 7←{5,6} |
| LASSO | 0.19999996825072291 | 7←{5,6} |
| Adaptive LASSO | 0.19999982683956946 | 7←{5,6} |

这些差异含正则收缩与浮点误差，不是“不同交互”。R3 仅验证每个数回到了正确的特征与边。

## 为什么 x₅² 不是两个源节点

第 133 行 `d[133,:]=[0,5,5]` 表示 x₅²，非零索引有两个，但不同源节点只有一个。原始 THIS 检查 `length(mon)==length(union(mon))`，这里 2≠1，因此整个单项式不会被解码成高阶边；它仍留在回归库中拟合动力学。

同样，目标 i 出现在源集合中时，原生规则不输出该交互。例如自衰减 `-1.1*x₇` 对目标 7 的拟合很重要，却不构成 7←7 边。不能按“系数非零”或“多项式次数为 2”直接断定三体边。

本项目提取的 [decode_coefficients](../src/this_adapter.jl) 保留原始 `this.jl` 的全部规则与阈值，测试覆盖：重复源排除、目标排除、恰等于 10^-8 不输出、刚大于 10^-8 输出、o=1/o=4 保留，以及两组 STLSQ 参数下与原生 Ainf 的逐矩阵精确一致。来源为 THIS commit `865efc43fe8ec21966659b482ca5756396974425`，GPL-3.0；未改上游文件。

## 文件桥接如何防止错位

[data_bridge.py](../src/data_bridge.py) 验证 CSV 形状、有限值、整数节点 ID、索引范围、首项常数、全部输入文件哈希、特征顺序哈希和索引条目数。`np.loadtxt(...,ndmin=2)` 防止单行/单列退化为向量。

Python 回写 `coefficients.csv` 后，最后写 `response.toml` 作为完成标记，其中包含请求 metadata 哈希、特征顺序哈希、系数形状和输出文件哈希。Julia 将返回标记与调用前保存的请求哈希比较，再核对输入/输出文件，防止把旧结果当作本次结果。已有结果或非空桥接目录拒绝覆盖；临时测试目录自动清除，正式交换文件留在 results/r3 便于验收。

单行、单列和 1×1 CSV 经 Julia→Python→Julia 的测试均精确相等，最大误差为 0。对真实 R1 数据，训练特征值和 d 与保存文件精确一致；测试也确认每个目标的真值系数与特征对应。

## 三种求解器和评价边界

普通 LASSO 在居中后的原始单位设计上使用等权 L1；Adaptive LASSO 复用只读 R2 求解器，其 Ridge 初值、尺度补偿、权重和回归均只拟合训练集。两者都把偏置放入同一常数列，并对同一组独立验证轨迹选择预先定义的 12 个 alpha 候选。这里没有把原始 THIS λ 当作 L1 alpha。

当前无噪声满模型残差方差接近零，沿用 R2 的明确决策：Adaptive LASSO 显式指定验证集模式，不强行运行 BIC。STLSQ 则沿用 R1 已锁定的 λ=0.03、ρ=0、niter=10，未在 R3 重新调参。

原始 THIS 实际返回 o=1…4，即使传入 `[2,3]` 也不筛选返回阶次。R3 完整保存这些行，但只评价 o=2/3。两个 L1 方法各产生一个约 1.62×10^-8 的常数偏置，按原阈值形成 o=1 行，已保留；这不计入本轮成对/三体指标。训练/验证导数预测使用完整系数矩阵，不能删除自衰减或常数项来计算误差。

三种求解器本次 F1/MCC 相同，只说明这个单种子干净数据上的接口工作正常。没有测试集选参、没有评价测试误差，也没有跨种子/噪声比较；后续是否有优势尚无结论。
